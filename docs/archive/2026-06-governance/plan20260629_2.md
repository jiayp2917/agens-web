## Key Decisions
- 标准局长：按 **90 回合**设计；事件不同可提前或延后。
- 20 回合目标：默认到 **练气后期/筑基门槛**；强天赋、高悟性、高风险路线可提前筑基，稳妥路线可延后到 22-28 回合。
- 属性系统：落地为 **六属性 30 点池**，手动每项 2-8；随机允许 0-10，并可能突破常规组合。
- 内容来源：采用 **抽象修仙套路库**，只借鉴共性，不直接使用真实小说人物、门派、剧情原文或专有设定。
- 资源系统：第一版不做显式资源栏；只保留状态型记录，如境界、年龄、寿元、称号、关系、关键机缘、伤势、因果、传承。
- 突破节奏：小境界默认不反复出现在选项里；大境界突破作为阶段事件出现，尤其筑基、金丹、元婴、化神、飞升。
- 叙事风格：编年史 + 偏爽文，但后端状态是权威；模型不能写已获得但系统未落账的奖励或境界变化。

## Implementation Changes
- 先补产品规格文档：把本次决策写入 `docs/GAME_MODE_SPEC.md`、`docs/RUNTIME_FLOW.md`、`docs/NEXT_GOVERNANCE_BACKLOG.md`，明确“玩法内容迭代阶段不大改功能架构”。
- 属性系统改造：前端角色创建改为 30 点池；后端 profile 校验同步改为 2-8/0-10 规则；如内部仍需 0-100，必须只作为兼容映射，不能暴露给玩家。
- 事件池第一版按 4 路线建设：稳健、机缘、风险、气运；每类至少覆盖练气、筑基、金丹三个阶段，每个阶段至少 8-12 个抽象事件模板。
- 世界观生成规则化：天赋/家世/灵根只影响世界观标签、初始势力、特殊人物关系、开局困境，不直接复制小说角色；特殊组合可触发特殊世界模板。
- 0-16 岁编年史：角色创建后先生成一段短编年史，说明出身、早年异象、家族/宗门关系、第一次接触修仙契机，再从 16 岁开始选择。
- 回合反馈：每 3-5 回合必须出现阶段性反馈，包括年龄变化、修为推进、外界大事、关系变化或风险伏笔。
- 状态落账：模型叙事中出现道具、升层、关系、伤势、称号、因果时，必须有结构化 `state_delta` 或被改写/拒绝，避免“文字说有，系统没有”。
- 结算循环：死亡/寿尽/飞升/主动结束后生成结算，奖励属性点、解锁稀有度、解锁特殊天赋/家世/灵根，并写入账号进度。
- 暂不大拆架构：`GameEngine`、`WebGameService`、`database_postgres.py` 只做与主流程直接相关的收束，不启动大规模 router/模块重构。

## Test Plan
- 单测：覆盖 30 点池校验、随机属性 0-10、手动属性 2-8、非法属性拒绝。
- 单测：覆盖天赋/家世/灵根影响世界标签和开局编年史，不允许直接复制真实小说专有内容。
- 单测：覆盖每 3-5 回合阶段反馈生成，且 `turn_count`、`game_turns.turn_no` 连续。
- 单测：覆盖模型叙事与 `state_delta` 不一致时的拒绝/改写逻辑。
- API 测试：本地 PostgreSQL 下 `tests\web` 不 skip，角色创建、开局、20 回合、存档、读档、结算链路可跑通。
- 前端验证：真实 Chrome 可见操作，完成角色创建、20 回合、存档、读档；记录是否卡顿、重复、状态冲突、fallback。
- 验收标准：20 回合内玩家能看到修仙成长、世界变化和至少一次明确阶段目标；不能出现 HTTP 200 不推进、回合缺号、叙事状态冲突。
