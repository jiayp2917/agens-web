P1：数据库内容库设计
目标：数据库先能支撑角色创建，不急着做完整世界模拟。
优先建这些 catalog 表：
catalog_talents
天赋名、稀有度、描述、属性修正、标签。
例：剑心、丹道、阵法、魔性、悟道、福缘。

catalog_family_backgrounds
家世名、描述、初始资源、初始风险、可触发剧情标签。
例：凡人孤儿、寒门弟子、修仙世家旁支、宗门杂役、散修之后。

catalog_spirit_roots
灵根类型、品级、修炼倾向、事件标签。
例：五行灵根、异灵根、天灵根、杂灵根。

catalog_difficulties
难度名、风险系数、收益系数、寿元/气运修正。

catalog_story_seeds
宗门、地域、秘境、敌对势力、机缘类型、劫数类型。
这些按主流修仙小说“共性套路”生成，不能直接复制具体小说的人物、门派、剧情原文。

P2：角色创建 → 世界观生成
目标：玩家创建角色后，后端调用大模型生成本局世界观，但世界观必须结构化落库。
流程：
玩家选择角色
六维：体魄、神魂、气运、悟性、心性、根骨。
天赋、家世、灵根、难度来自数据库。

后端组装 world prompt
输入：角色、天赋、家世、灵根、难度、内容库标签。
输出必须是 JSON，不允许只返回散文。

生成并保存世界观
world_profile：世界名、地域、宗门格局、主要势力、修炼体系、当前矛盾。
initial_situation：角色起点、当前处境、第一组 A/B/C/D。
world_rules：本局特殊规则，但不暴露给前端隐藏细节。

模型失败兜底
使用本地模板生成默认世界观。
不能因为模型失败卡住新游戏。

P3：世界观下生成故事并游玩
目标：每回合在同一世界观下推进，不再每次随便生成。
每回合流程：
玩家选 A/B/C/D。
后端规则引擎先结算：时间流逝。
属性变化。
寿元变化。
突破/失败/死亡/机缘。

大模型只负责短文本润色：本回合叙事。
外界大事摘要。
下一轮 A/B/C/D 文案。

保存 game_turns：turn_no
elapsed_years
choice_taken
state_delta
state_after
calendar_summary
narrative
choices

核心原则：数值和生死由后端决定，模型只写故事。
